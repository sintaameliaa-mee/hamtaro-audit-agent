🐹 Hamtaro Audit Agent

A coverage-led security audit agent — live demo for the Agent Games Season 01 Wildcard track.

Honest scope — read this first.

This endpoint is the agent's deterministic pre-screen: it runs seven fixed pattern checks over a Solidity snippet in pure JavaScript — no Foundry, no compilation, no external calls. Every finding it returns is verdict: needs_validation, because confirmation needs a runnable PoC and an independent verifier.

The full multi-agent audit — reconnaissance, coverage ledger, parallel hunters, critic waves, independent verification — runs in Muse following skill/SKILL.md, and is evidenced by the sample runs below. This endpoint does not run the full audit, and does not claim to.

What the agent does

Given a target codebase and a scope, the agent runs a six-phase audit. It only reports a finding after an independent verifier — a fresh agent that did not hunt it — has tried, and failed, to refute it.

reconnaissance → coverage ledger → parallel hunters → critic waves → independent verification → validated findings → report
  1. Reconnaissance maps the architecture, trust boundaries, and input surfaces, then seeds a deterministic coverage-ledger.json — every unit is planned before hunting starts.
  2. Coverage-led hunting assigns one isolated hunter per boundary; coverage critics run in waves until no new gap is found.
  3. Candidate validation hands every candidate to a fresh verifier whose job is to refute it from source and bounded local evidence. A candidate survives only if the verifier cannot kill it.
  4. Structured output writes confirmed / needs_validation / rejected records to findings.json, validated against a JSON schema with a zero-dependency Node validator.
  5. Independent record verification re-checks the final source claims with fresh agents; a material correction gets another verifier.
  6. Reporting derives REPORT.md, FINDINGS-DETAIL.md, and NEEDS-VALIDATION.md from the verified records and the ledger.

Worked example — the demo run

The repo's demo/ runs the full pipeline end-to-end against a tiny vault with one intentional, labelled reentrancy bug. The committed artifacts are the output of a real run — inspect them without running anything:

DemoVault.withdraw — reentrancy, confirmed (high)

withdraw() sends ETH to the caller before zeroing the caller's recorded balance, so a malicious receiver re-enters withdraw() and is paid its full balance again on every re-entry. A 1-ether attacker drains the entire vault — 11 ether out, 10 of them victim funds, 10 reentrant calls.

Confirmed by a passing Foundry PoC (testReentrancyDrainsVault), independently re-run, with a passing counterfactual against the fixed vault (testFixedVaultBlocksReentrancy).

  • demo/out/findings.json — the confirmed finding record
  • demo/out/demo-report.md — the demo report
  • demo/out/coverage-ledger.json — the coverage ledger
  • demo/src/DemoVault.sol — the vulnerable vault (intentional bug, labelled)
  • demo/test/DemoVault.t.sol — the Foundry PoC tests

Run it yourself: node demo/run-demo.cjs (Node 18+ and Foundry). Under a minute.

Real runs — two audits, zero findings, on purpose

  • Cronos chain code (Go) — 7/7 units, 127 paths, 70 checks → 0 findings. artifacts
  • 8 VVS Finance contracts (Solidity) — 12/12 units, ~2,105 lines, 41 PoC tests → 0 findings. artifacts

Both runs document their strongest leads and why the evidence killed them. A verifier that cannot be talked out of killing a weak candidate is the feature, not a failure: the output is “no finding” with receipts, instead of a confident-sounding false positive.

API

POST /api/audit with {"code": "<Solidity source>"} returns verdict + findings in the repo's findings.json record shape. GET /api/audit returns usage. Seven checks: reentrancy, tx.origin, unchecked low-level call, selfdestruct, delegatecall, division-before-multiplication (heuristic), missing access control (heuristic).

curl -X POST "$URL/api/audit" -H "Content-Type: application/json" \
  -d '{"code":"contract V { function w() external { (bool ok,) = msg.sender.call{value: 1}(\"\"); require(ok); } }"}'
